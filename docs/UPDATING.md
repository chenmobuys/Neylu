# 更新与排错

简体中文 · [English](UPDATING.en.md)

开机启动在 macOS 12 使用系统兼容接口，macOS 13+ 使用 SMAppService；仅调整构建期兼容封装，不改变开机启动行为或已保存设置。

## 更新方式

- 在设置中选择「检查更新…」，找到新版后点击「立即更新」。
- Homebrew 安装的用户可执行 `brew update && brew upgrade --cask --greedy neylu`；`--greedy` 会包含有内置更新器的 App。
- 也可从 [GitHub Releases](https://github.com/chenmobuys/Neylu/releases) 下载对应芯片的 DMG，退出 Neylu 后手动替换。

默认每天后台检查一次，发现新版后在设置按钮显示提示点，菜单显示版本号；不自动弹窗、不自动下载安装包。可在「偏好设置」关闭「自动检查更新」。所有安装版本默认只检查正式版，包括当前安装的是 Alpha、Beta 或 RC。需要测试更新时，在「偏好设置 → 测试版更新」主动选择「Neylu 测试版」，才会包含 Alpha、Beta 和 RC；默认是「关闭」。选择跨重启保存，手动和后台检查遵循同一设置。关闭后清除不再适用的测试版提示，并取消旧通道的进行中操作；这不会将已安装版本降级。

## 首次打开或更新器被拦截

当前发行包未经 Apple 公证。确认安装包来自本仓库、且你信任该版本后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)通过「系统设置 → 隐私与安全性 → 仍要打开」允许启动。

也可手动处理 Neylu 的下载隔离标记：

```sh
xattr -dr com.apple.quarantine "/Applications/Neylu.app"
```

如果提示对象是 `NeyluUpdater`，先点「完成」并取消更新，再执行上述命令并重试。修复从 alpha.6 起提供；从旧版升级时仍由旧更新器执行，因此这一次可能仍需手动处理。若 App 安装在其他目录，请修改路径。

这不会关闭 Gatekeeper 或 SIP，也不能修复签名损坏或架构不兼容。若系统明确提示恶意软件会损害电脑，不要用此命令绕过。重新下载或手动更新后，系统可能要求再次批准；组织管理的 Mac 可能不允许自行添加例外。

Homebrew 会打印适配安装路径的中英文首次打开说明，但不会自动执行这条命令。`brew uninstall --cask neylu` 保留本地数据；加 `--zap` 会删除历史与偏好设置。

## 更新检查与安装校验

alpha.5 起，客户端通过架构独立的静态 appcast 检查更新，不访问 GitHub REST API，不需要账号或 Token。Alpha 7 及以前，手动与后台检查共享一分钟内的缓存和进行中的请求，静态 CDN 的缓存可能延迟新版发现。alpha.8 起修复：手动检查绕过已完成缓存，每次订阅传输使用新的缓存键并请求重新验证；后台保留一分钟缓存，并发请求仍合并。此修复仅在安装 alpha.8 或更新版本后生效。更早版本仍使用旧接口；遇到限流时可通过 Homebrew 或 DMG 升级。

安装包由 GitHub Releases 提供，校验值由发布工作流核对后写入 appcast。更新器验证 SHA-256、完整版本、架构、最低系统要求、应用标识及代码签名；已有 Developer ID 的安装还约束 Apple 签名链与 Team ID。alpha.6 起，验证已安装 App 及复制后的辅助程序后，仅处理私有暂存辅助程序副本的隔离标记；不修改来源 App、下载的候选应用或其他元数据。

点击「立即更新」后，Neylu 正常退出、替换并重启。替换或启动请求失败，或新版在短暂启动观察期内退出时，会恢复原安装。历史与偏好保存在 App 外，不随替换删除。DMG 内运行、App Translocation 或安装位置不可安全替换时，改为打开已验证 DMG 手动安装，不请求管理员权限。

这些校验不能替代 Apple 公证；当前预发布版的来源信任仍依赖本仓库 GitHub HTTPS 渠道。若想核对手动下载的文件，可将输出与 Release 附件旁的 SHA-256 摘要比较：

```sh
shasum -a 256 ~/Downloads/Neylu-*.dmg
```

命令会列出下载目录中匹配的安装包，请核对实际安装的那一份。不会额外发布 SHA-256 文件或 manifest。

## 数据与兼容性

监控数据不上传，无遥测。CPU、GPU、内存、网络历史在 `~/Library/Application Support/Neylu/history.sqlite` 保留 24 小时；目录权限为 0700，数据库及 WAL 为 0600。在「偏好设置 → 图表时间范围」可切换两分钟、十五分钟和一小时；只缩减绘图点，SQLite 保留原始记录。运行与采样定义见[指标说明](METRICS.md)。

alpha.5 起支持 macOS 12 及以上；更早版本要求 macOS 13。两种架构均有 CI 构建与回归，传感器在 M3 Max 上实际验证；macOS 12 尚未实机验证，其他硬件读数可能不可用。

报告问题时请提供 Neylu 版本、macOS 版本、芯片和错误文字；IP、本机路径等诊断信息请先脱敏。安全问题按[安全反馈](../SECURITY.md)私下报告。

## 省电模式与诊断

「偏好设置 → 省电模式」按「跟随系统、开启、关闭」排列，默认关闭；「跟随系统」按 macOS 低电量模式自动调整。生效时详情关闭后的采样间隔至少五秒，打开详情恢复已设定的刷新间隔。后台历史继续记录；磁盘读写等详情专用采集会暂停，重新打开先建立基线。温度在详情可见或菜单栏温度指标启用时采样，最多每五秒读取一次。

在设置菜单或关于窗口选择「复制诊断信息」，可复制版本、系统、处理器、刷新策略和指标可用性；不包含 IP、网卡/磁盘名、路径、日志或实际监控数值，也不会自动发送。详情关闭时，部分状态显示「不可用或尚未采样」是正常行为，不表示硬件不受支持。

## 显示与图表交互

「菜单栏显示…」只提供预览与指标勾选排序，恢复默认布局位于指标标题右侧。菜单栏内存统一显示使用率并保持稳定宽度，详情保留已用、可用和总量。CPU 温度默认不显示，可在受支持设备上勾选和排序；暂时无法读取时显示“—”。「偏好设置 → 单位进制」统一选择十进制或二进制；网速保持字节每秒，不提供独立比特模式。恢复默认布局只重置指标顺序和勾选状态，不清除格式、历史或其他偏好。

点击任一图表可固定四个图表的时间范围和读数；后台采样与菜单栏实时读数继续更新。再次点击图表或顶部播放按钮恢复实时图表；关闭详情或切换历史范围也会恢复实时。只有实际采样点可被选中。提示跟随选中时间并限制在图内，固定时标题显示「图表已固定」。在「偏好设置 → 图表时间范围」选择「近 2 分钟／近 15 分钟／近 1 小时」，与刷新间隔分别设置；详情顶部不再展示范围选择。

点击详情网络区 IP 旁的眼睛按钮可遮挡地址及其悬浮提示；再次点击恢复显示。此选项会保存到下次启动，诊断复制始终不包含 IP。

在「偏好设置 → 全局快捷键…」点击输入框录入包含 Control、Option 或 Command＋Shift 的组合键，点击“保存”确认，打开或关闭详情；未录入有效组合时保存不可用。默认不启用，可随时移除；冲突时保留原快捷键。按物理键位保存，切换键盘布局后可先移除再录入，以更新显示名称。使用系统快捷键注册接口，无需辅助功能权限，也不监听全局键盘输入。

## 失败与重试

版本信息异常时重新检查；网络中断、校验或应用验证失败时重新下载并重新校验；安装或启动阶段失败时可重试安装，也可前往下载页使用 DMG。错误说明会给出对应操作，不复用校验失败的包。

关闭或取消更新会使旧任务的回调失效，重新打开可以立即重新检查。每次操作独立拥有权限为 0700 的临时目录，失败或取消只清理该次目录；等待后台准备结束后再清理。已移交给更新辅助程序的文件由辅助程序处理，已交给 Finder 的手动安装 DMG 保留供安装使用；若系统仍占用挂载映像，不递归删除该挂载点，也不强制卸载。

[下载页面](https://github.com/chenmobuys/Neylu/blob/updates/downloads.md)按语义版本选择两种架构都已公开的最新安装包，并显示各自系统要求，不依赖 GitHub 发布列表的位置。

## 更新操作的超时与取消

手动检查完成后，尚未返回的旧后台检查不会覆盖它的更新提示。安装准备的系统命令默认最多等待 120 秒，应用复制最多 300 秒；输出超过 1 MiB 时中止。取消会停止本次命令并回收子进程，然后清理本次私有文件。卸载映像单次最多等待 30 秒，仅磁盘忙时有限重试，不强制卸载；未能卸载时保留挂载目录，避免递归删除映像内容。

App 内的测试版选择不控制 Homebrew。默认 Cask 首次进入正式版后，只跟进后续正式版；首次正式发布前仍可提供预发布包。测试版可通过上述 App 内选项或对应 DMG 主动安装。
